# PRD｜「智析 BizInsight」电商数据分析 Agent

> V5.0 · 作品集整理版

## 1. 产品概述

「智析 BizInsight」面向电商运营人员，帮助用户从经营数据中完成从**异常发现 → 指标拆解 → 数据分析 → 原因假设 → 证据验证 → 复盘输出**的一体化分析任务。

产品的核心不是替用户“查一个数”，而是降低运营组织一次完整经营分析的成本。

### 核心用户

- **店铺电商运营**：关注店铺销售、商品、渠道、转化等经营问题。
- **平台电商运营**：需要从更大范围的数据中识别异常、定位问题并形成经营判断。

### MVP 数据入口

前期通过用户上传 CSV / Excel 文件进入分析流程；后续逐步接入数据库、数仓及业务 API。

---

## 2. 产品核心任务

用户可以直接提出：

- “最近销售额为什么下降？”
- “哪些商品拖累了 GMV？”
- “哪个渠道的表现出现异常？”
- “帮我生成这周的经营复盘。”

Agent 不直接跳到“原因结论”，而按照以下路径组织分析：

```text
发现异常
   ↓
拆解指标
   ↓
分析贡献
   ↓
扫描关联因素
   ↓
形成候选假设
   ↓
证据门控（Evidence Gate）
   ↓
验证假设 / 暴露证据缺口
   ↓
输出复盘结论
```

---

## 3. 数据与字段

系统首先解析用户文件并建立字段映射，例如：

| 业务含义 | 可能字段 |
| --- | --- |
| 时间 | date / 日期 |
| 商品 | product / SKU |
| 渠道 | channel |
| 销售额 | sales / GMV |
| 订单 | orders |
| 访客 | UV |
| 点击 | clicks |
| 转化 | conversion |

关键字段进入分析前必须经过人工确认，避免字段语义错误进入后续分析链路。

---

## 4. 数据质量检查

分析前检查：

- 必要字段是否存在
- 时间字段是否可解析
- 是否存在重复记录
- 数值字段是否存在异常格式
- 是否存在缺失值
- 金额、订单等关键指标是否存在明显异常

数据质量不满足分析要求时，不继续输出高置信结论，而是向用户暴露数据问题。

---

## 5. 指标分析

### 5.1 指标聚合

对用户选择的时间、商品、渠道等维度进行确定性聚合。

### 5.2 趋势分析

计算指标时间序列，支持观察：

- 上升 / 下降趋势
- 波动
- 环比 / 同比变化
- 异常点

### 5.3 异常检测

异常检测用于回答：

> **“哪里值得进一步分析？”**

异常本身不等于原因，而是后续分析的入口。

---

## 6. 指标拆解与贡献分析

发现异常后，先回答：

> **“整体变化主要是谁贡献的？”**

例如：

```text
上周 GMV：1000 万
本周 GMV：860 万
下降：140 万

商品 A：-60 万
商品 B：-40 万
其他：-40 万

A 对整体下降的贡献：42.9%
```

贡献拆解结果必须通过守恒校验，确保各维度贡献与总体变化能够核对。

### 重要产品边界

“贡献”只代表对结果变化的数学贡献，不直接等于“原因”。

因此系统不会把：

> 商品 A 销售下降

直接表述成：

> 商品 A 导致 GMV 下降。

---

## 7. 原因分析与假设验证

### 7.1 因素扫描

在贡献者确定后，系统进一步扫描可能关联的因素，例如：

- 流量变化
- 点击率变化
- 转化率变化
- 客单价变化
- 库存变化
- 活动变化
- 渠道变化

因素扫描只负责产生**候选因素**，不直接升级为因果结论。

### 7.2 证据门控 Evidence Gate

对每个候选原因进行证据判断：

```text
候选原因
   ↓
是否存在数据证据？
   ├─ 是 → 进入假设验证
   └─ 否 → 暴露证据缺口
```

证据不足时，系统可以建议：

- 补充数据
- 继续查看关联指标
- 结束当前分析并保留待验证假设

### 7.3 假设验证

当前阶段重点验证简单、可计算的经营假设，例如：

- GMV 下降是否主要来自 UV 下降？
- 转化率下降是否与 GMV 下降同步？
- 某渠道是否显著偏离整体趋势？

输出：

> **支持 / 不支持 / 证据不足**

而不是强行输出“真正原因”。

---

## 8. 复盘输出

最终将分析结果整理为结构化复盘摘要：

```text
现象
↓
关键数据
↓
主要贡献者
↓
关联证据
↓
待验证假设
↓
证据缺口
↓
建议下一步
```

Agent 不替用户做调价、补货、投放等经营动作，只提供分析事实、证据、假设和低风险验证建议。

## 9. Agent 工具

| 工具 | 作用 |
| --- | --- |
| file_parse_upload | 文件解析与字段映射 |
| data_quality_check | 数据质量检查 |
| metric_aggregate | 指标聚合 |
| trend_compute | 趋势计算 |
| comparison_compute | 环比 / 同比计算 |
| contribution_decompose | 指标贡献拆解 |
| factor_scan | 候选因素扫描 |
| hypothesis_verify | 假设验证 |
| nlg_render | 自然语言解释 |
| dashboard_render | 数据展示 |
| report_export | 复盘摘要导出 |

核心原则：**LLM 负责理解、规划与解释；业务数字由确定性计算工具产生。**

---

## 10. 可信度与安全

### 10.1 数字事实来源

用户上传的数据是第一方事实来源；指标口径库负责保持业务定义一致；领域知识只用于提供候选解释。

### 10.2 数值一致性

关键数字必须来自计算工具，并在 NLG 层进行一致性检查。

### 10.3 结论分级

系统区分：

- 事实
- 贡献证据
- 关联证据
- 待验证假设
- 验证路径

### 10.4 安全边界

- 只分析，不直接执行经营动作
- 数据不跨租户访问
- 不允许未经授权的数据外泄
- 关键操作记录审计日志
- 敏感操作需要二次确认

## 11. 指标体系

### 北极星指标

**有效分析闭环率 / 任务完成率**

### 用户价值

- 分析任务完成时长
- 用户追问次数
- 人工核对次数
- 复盘材料修改量
- 结论认同率

### AI / 分析质量

- 关键事实正确率
- 计算一致性
- 贡献分解正确性
- 无证据断言率
- Evidence Gate 正确率

## 12. 产品假设与验证

目前项目不虚构真实用户研究结果，核心假设需要通过真实用户验证：

**H1**：运营在经营复盘中的主要成本是组织分析路径，而不仅是取数。  
**H2**：用户愿意让 Agent 组织分析路径，但希望保留最终经营判断。  
**H3**：确定性计算与证据链能够提升用户信任并降低人工复核成本。  
**H4**：结构化字段映射、可追溯计算和证据链相比直接让通用大模型分析文件，能够获得更稳定的结果。

建议采用半结构化访谈 + 任务可用性测试验证：

- 完成时长
- 分析步骤数
- 追问次数
- 人工核对次数
- 复盘材料修改量

## 14. 产品设计底线

> **宁可少说、不说错。**

- 不让 LLM 直接计算关键业务数字
- 不把相关性包装成因果
- 证据不足时明确暴露缺口
- 所有关键数字可追溯、可复核
- Agent 不越权执行经营动作
