这里记录我对真实问题的观察、产品机会的判断，以及从 **想法 → 产品定义 → 方案设计 → 原型 / Demo → 迭代** 的完整过程。

- 如何发现问题，以及为什么认为它值得解决

- 如何在目标、成本、体验与商业模式之间做取舍

### 02 · 「智析 BizInsight」｜电商数据分析 Agent

**关键词：** B 端 · AI Agent · 数据分析 · 经营诊断 · 证据链 · 人机协作 · AI 产品化

#### 这是一个什么产品？

「智析 BizInsight」是一款面向**店铺电商运营与平台电商运营**的经营分析 Agent。

它不是把传统 BI 搬进聊天框，也不是一个只会生成 SQL 的 ChatBI。它希望解决的是经营复盘中更高成本的一段工作：**当运营发现“销售下降”之后，下一步到底应该分析什么、看哪些数据、如何判断可能原因，以及怎样形成可信的复盘结论。**

产品将一次经营分析组织成连续任务：

> **异常发现 → 指标拆解 → 贡献分析 → 因素扫描 → 假设验证 → 复盘输出**

前期以用户上传 CSV / Excel 文件作为数据入口，后续可进一步接入数据库、数仓与业务 API。

#### 为什么做这个产品？

传统 BI 已经很好地解决了“**发生了什么**”，但运营真正困难的往往是：

> **“我知道销售下降了，但接下来该看什么？”**

因此我没有把产品价值定义成“让 AI 帮我查数”，而是定义成：

> **降低运营组织一次完整经营分析的认知与操作成本。**

同时，经营分析不能把“相关”直接说成“因果”。因此产品从异常发现开始，先拆解指标、寻找主要贡献者，再寻找关联证据，并通过 Evidence Gate 判断证据是否足够；证据不足时明确暴露缺口，而不是让模型补出一个听起来合理的原因。

#### 核心功能

| 功能 | 解决什么问题 |
| --- | --- |
| **文件上传与字段映射** | 快速接入 CSV / Excel，并将原始字段映射为可分析的业务字段 |
| **数据质量检查** | 在分析前发现缺失字段、时间异常、重复记录等问题，避免脏数据进入结论链路 |
| **指标趋势与异常发现** | 快速定位销售、GMV 等经营指标的异常变化 |
| **指标拆解与贡献分析** | 回答“整体下降主要是谁贡献的”，并通过守恒校验保证结果可核对 |
| **因素扫描** | 围绕流量、点击率、转化率、客单价、库存、活动、渠道等寻找候选因素 |
| **假设验证** | 对简单经营假设进行数据验证，输出“支持 / 不支持 / 证据不足” |
| **证据链与复盘摘要** | 将事实、贡献证据、关联证据、待验证假设和验证路径组织成可复核的复盘结果 |
| **AI 分析助手** | 通过自然语言理解用户问题，并自动组织后续分析路径 |

#### 一个关键的产品判断

**我不希望 Agent 替运营做经营决策。**

智析的边界是：

```text
AI：发现异常 → 拆解 → 分析 → 验证 → 解释
                         ↓
                   人：最终判断与执行
```

Agent 可以告诉运营：**“商品 A 贡献了本次 GMV 下降的 42.9%，其转化率也同步下降，但现有数据不足以证明二者存在因果关系；建议补充活动 / 库存数据进行验证。”**

但不会直接告诉运营：**“马上给商品 A 降价 / 增加投放。”**

这也是我对 B 端 AI 产品的一个核心判断：**AI 的价值不只是替人完成更多动作，而是帮助人在复杂业务中更快形成可靠判断，同时把决策权留在业务人员手里。**
